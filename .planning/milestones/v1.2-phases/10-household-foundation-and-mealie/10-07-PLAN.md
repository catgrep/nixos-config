<objective>
Prove MEAL-05 the way it can only be proven: create real household data, reboot ser8 twice, and confirm both of Mealie's independent state stores came back intact — while simultaneously proving the impermanence rollback that makes the test meaningful is actually firing.

Purpose: this is the criterion most likely to pass for the wrong reason. If ser8's boot-time ZFS rollback silently stopped working, nothing gets erased, everything survives, and MEAL-05 "passes" while telling you nothing. And if the check only counts PostgreSQL rows, it passes while every recipe thumbnail is broken and every user has been logged out, because Mealie keeps images, uploads, and its token-signing secret on disk rather than in the database. This plan closes both holes.

D-12 settles a related question: ser8 has already been rebooted on 26.05, so the boot path is exercised and these two reboots are pure persistence checks rather than boot-path validation.

Output: two consecutive reboots survived, with byte-level evidence for the file store, row-level evidence for the database, session-level evidence for the secret, and a negative control proving the rollback still erases what it is supposed to.
</objective>
