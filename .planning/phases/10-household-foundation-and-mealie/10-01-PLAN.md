<planner_decisions>
Two Claude's-Discretion items from CONTEXT.md are decided here so the executor does not re-open them.

**PD-01 — Mealie runs as a static `mealie` system user, not under `DynamicUser`** (RESEARCH.md Decision Point 1, Option B). CONTEXT.md's `## Canonical References` summary line "Mealie needs zero new impermanence entries" describes Option A and is superseded by this decision. Rationale: FOUND-03 asks for a pattern the remaining three services reuse; Homebox ships a static user upstream and the 26.05 `services.actual` module exposes `user`/`group`, so a `DynamicUser`-shaped pattern generalises to neither. `modules/media/prowlarr.nix` is the in-repo precedent for exactly this override. Secondary benefits: state lands at a real `/persist/var/lib/mealie` matching the repo's `/persist/var/lib/<svc>` convention, Phase 11's backup job does not need root to descend into a `0700` `/var/lib/private`, and MEAL-05 becomes directly inspectable. Reversibility: `costly` — changing after data exists means a manual `mv` plus `chown` of the state tree, but changing now, before first activation, is free.

**PD-02 — `modules/household/postgresql.nix` is deliberately NOT created.** RESEARCH.md Decision Point 2 puts the version pin in the host-policy layer, and there is no non-version hygiene left for a reusable file to carry: PostgreSQL listens on a unix socket only (no firewall port), and the upstream module already creates the `postgres` user, group, and `StateDirectory`. An empty module is worse than no module (CLAUDE.md: no premature abstraction). `hosts/ser8/household/postgresql.nix` exists with no reusable counterpart, and that asymmetry is intentional.
</planner_decisions>

<assumption_delta_decision>
**Noun now primary:** service *module group* (was singular: `modules/media/` was the only one; this phase adds `modules/household/` as the second).

**Decision:** `promote`.

**Rationale:** The two-layer split — reusable `modules/<group>/<svc>.nix` declaring user/group/firewall/systemd overrides with `enable = lib.mkDefault false`, paired with `hosts/<host>/<group>/<svc>.nix` carrying enablement, pins, URLs, and secrets — becomes the repo-wide convention for every service group, not a `media`-specific arrangement. FOUND-03 states this outright ("a pattern the remaining three services reuse"), and Phases 12-13 add Homebox, Actual, and Donetick into `modules/household/` by copying rather than re-deciding. This is not accepted debt; it is the generalisation the phase goal asks for.

**Suggested invariant test (not built this phase):** an evaluation-time assertion that every file under `modules/*/` sets its service's `enable` to a defaultable false and guards its `config` stanzas on that `enable` — encoding "importing a reusable module is inert" as a checked property rather than a convention.
</assumption_delta_decision>
