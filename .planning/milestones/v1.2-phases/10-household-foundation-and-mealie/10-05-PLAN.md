<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet client -> firebat tsnet listener | Untrusted household device traffic terminates TLS at the caddy-tailscale node |
| firebat -> ser8 tcp/9000 | Plaintext HTTP over the LAN; the hop the tsnet vhost proxies across |
| Tailscale control plane -> tailnet node registry | A new node name is claimed using a shared authentication key and persists outside this repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-08 | Tampering | orphaned tsnet node if the gateway change is reverted | low | accept | The node is runtime tailnet state, not repository state, and no automated control removes it. Task 2 records the manual removal step in the SUMMARY so a future rollback does not leave a stale claimed name that another host could be pointed at |
| T-10-03 | Spoofing | forwarded headers arriving at gunicorn from the proxy | medium | mitigate | The forwarded-address trust list was pinned to firebat's LAN address in plan 10-01 rather than a wildcard; this plan proves the resulting links carry the HTTPS tsnet URL rather than a downgraded scheme |
| T-10-17 | Information Disclosure | a wrongly scoped tsnet vhost exposing an unintended backend | medium | mitigate | The gateway suite's route extraction is compared per-test against the pre-activation transcript, and the default server's route count must be unchanged; a vhost landing in the wrong server is exactly what a LAN-domain block for Mealie would have caused and what D-02 forbids |
| T-10-18 | Spoofing | an untrusted or self-signed certificate accepted out of habit | medium | mitigate | The blocking human checkpoint requires opening the certificate details and confirming a public issuer, because every LAN-domain name in this repository uses a local certificate authority and a household member would otherwise be trained to click through warnings |
| T-10-19 | Repudiation | claiming end-to-end reachability from a loopback probe | high | mitigate | Every reachability assertion in this plan originates from a tailnet member against the public name, and specifically rejects 502 and 000 rather than accepting any non-error; the loopback proof was plan 10-04's and is deliberately not reused here |
| T-10-SC | Tampering | npm/pip/cargo installs | low | accept | No public-registry install occurs; the Caddy Tailscale plugin is pinned to an exact Go pseudo-version with a vendor hash (RESEARCH.md Package Legitimacy Audit: zero `[SLOP]`, zero `[SUS]`) |
</threat_model>
