    The `remote` helper collapses every failure mode — unreachable host, ssh auth failure, `journalctl` missing, deploy user lacking `systemd-journal`/`adm` membership — into an empty string. `test_hass_no_startup_errors` then reads empty as "no error entries", so an unreachable ser8 scores a pass. The zfs and confinement scripts avoid this because every command they run returns non-empty output on success, so empty is unambiguously a failure. That trick does not transfer here: an empty journal query is the healthy outcome. The status of the remote command must therefore be carried out-of-band.

    Replace `remote` with `remote_probe`, keeping the existing `printf -v remote_command '%q ' "$@"` escaping and the existing `2>/dev/null` on the ssh call. Append to the escaped remote command a trailing `; printf '__RC=%d\n' $?` so the remote shell emits, as its own final line, the exit status of the command that was asked for. Add `-o BatchMode=yes` and `-o ConnectTimeout=10` to the ssh invocation so an unreachable target fails fast and never blocks on a password prompt. `remote_probe` returns ssh's own exit status and prints whatever came back on stdout; it must not append `|| echo ""` or any other swallow.

    Callers parse the result by taking the LAST line of the captured output and matching it against the `__RC=` prefix — match on the last line specifically, not with a substring search over the whole payload, because journal text could itself contain that token. Absence of a well-formed `__RC=` final line means the remote command never ran to completion (ssh transport or auth failure) and is always a failure.

    Rewrite the three tests against that contract:
    - `test_hass_unit_active` keeps its current exit-status semantics (it already reads ssh's status correctly). Add the same `-o BatchMode=yes -o ConnectTimeout=10` options to its direct ssh call so all three tests share one connection behavior.
    - `test_hass_http` uses `remote_probe`. A missing `__RC=` final line fails with a message naming the host and stating that the probe could not be run over ssh. A present-but-non-zero `__RC=` value fails naming curl's exit status. Only when the value is 0 does the existing HTTP-code case statement run, unchanged, over the payload with the sentinel line stripped.
    - `test_hass_no_startup_errors` uses `remote_probe`. A missing or non-zero `__RC=` value fails with a message stating the journal for `$HASS_UNIT` on `$host` could not be read. Only when the value is 0 is the payload interpreted: empty means genuinely zero error-level entries and passes; non-empty keeps the existing count-and-print-first-ten failure path.

    Update the file's header comment so it describes the readability requirement it now enforces, and update the comment above `remote_probe` to state the contract (status carried by the sentinel, absence of the sentinel is a failure) the way `test-zfs-health.sh` states its own.
