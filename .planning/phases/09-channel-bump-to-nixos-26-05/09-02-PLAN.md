<objective>
Move both Raspberry Pi hosts off the third-party `nvmd/nixos-raspberrypi` fork (and its bundled nixpkgs fork) onto upstream `nixpkgs` plus `nixos-hardware`, so all four hosts build from one supported channel and one `nixosSystem` entry point (D-01).

Purpose: this is FOUND-02 and the second half of FOUND-01. The fork was carrying real engineering — config.txt rendering, firmware staging, DTB pruning — but upstream `nixos-hardware` has since absorbed that machinery with attribution, so the migration is a rename of option paths rather than a reimplementation. Removing the fork also drops a third-party nixpkgs fork and a third-party trusted binary cache from the supply chain, and the trust grant only actually goes away when the daemon configuration is re-applied.

Output: a flake with no fork input and no `mkPiSystem` helper, two Pi host directories with proper `default.nix` entry points, a Pi base module that reads upstream bootloader and kernel options, pi5's config.txt rewritten to the upstream schema, a permanent eval assertion that both Pis really are on extlinux with a mainline kernel, and an honest per-host evidence record.

Scope boundary (D-06/D-07): this plan is build-compat only. No image is built, nothing is flashed, and neither Pi is activated. pi4's AdGuard DNS is physically disconnected and pending retirement; pi5 keeps running its current generation.
</objective>
