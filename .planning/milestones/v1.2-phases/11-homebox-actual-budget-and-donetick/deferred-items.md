# Phase 11 deferred items

Out-of-scope discoveries found during execution. Not fixed by the plan that found them.

## `environment.persistence."/persist".directories` cannot be `nix eval --json`'d directly

- **Found during:** plan 11-04, Task 2, writing `scripts/validation/test-donetick-module.sh`
- **What:** `nix eval --json '.#nixosConfigurations.ser8.config.environment.persistence."/persist".directories'` fails for every host and every entry, not just Donetick's: `error: The option 'method' can no longer be used since it's been removed. As real bind mounts are now used instead of bindfs, changing the directory linking method is deprecated.` The failure is on `[definition 1-entry 1]` -- the very first list entry (`"/etc/nixos"`, a plain string, nothing Donetick-related) -- proving this is unconditional and repo-wide, not something plan 11-04 introduced.
- **Diagnosis:** `nix eval --json` recursively serializes every field of every list-entry submodule, including an internal `method` suboption the pinned `impermanence` flake input removed upstream. Consuming code inside the impermanence module itself never reads `.method`, so the option works fine at activation/build time -- only a raw `--json` dump of the whole `directories` list trips over the dead option.
- **Why out of scope:** pre-existing, caused by the pinned `impermanence` input version, unrelated to any household service's configuration. Not something plan 11-04's own files can fix without an unrelated flake-input-level change.
- **Workaround applied (11-04 only, not a fix):** `test-donetick-module.sh` uses `nix eval --json --apply 'dirs: ... map (d: if builtins.isString d then d else d.directory) dirs ...'` instead of a bare `--json` dump, plucking only `.directory` per entry and never forcing `.method`. This sidesteps the dead option without touching the impermanence input or any other household module's persistence entries. `test-mealie-module.sh`, `test-homebox-module.sh`, and `test-actual-module.sh` do not assert against `.directories` at all today, so they are unaffected but would need the same workaround if extended to do so.
- **Suggested fix (not applied):** update or patch the `impermanence` flake input to a version whose `directories` submodule no longer declares a dead `method` option at all, or file/track upstream.

## `make reboot-test-ser8` does not exit 0, purely on the pre-existing NordVPN suite

- **Found during:** plan 11-06, Task 1, the real ser8 reboot drill
- **What:** `make reboot-test-ser8` reboots ser8 and runs `scripts/smoketests/ser8/all.sh`. Post-reboot, the `household` suite is 8/8 (all three Phase 11 apps plus Mealie), `media` is green, `test-zfs-health.sh`, `test-vaapi.sh`, and `test-home-assistant.sh` are all green -- the only failing area is `nordvpn`, at 2/4 (`test-forwarding.sh` and `test-qbittorrent.sh` fail; `test-veth-interfaces.sh` and `test-qbittorrent-confinement.sh` pass). This makes the top-level `ser8` suite 6/7 and `make reboot-test-ser8` exit 1.
- **Diagnosis:** identical to the two pre-existing NordVPN entries already logged in `STATE.md`'s Blockers/Concerns (dated before Phase 9's channel bump): the tunnel/DNS-forwarding path is broken (`Local AdGuard DNS (192.168.68.56): FAILED`, `External connectivity from qBittorrent namespace: FAILED`), and `test-forwarding.sh` queries a retired pi4 resolver address that no longer serves DNS. Both failure signatures match STATE.md's existing notes verbatim. This reboot did not introduce a new failure -- `wgnord.service`, `wgnord-monitor.service`, and `netns@wgnord.service` are all ACTIVE post-reboot, the veth bridge and WireGuard interface are up, and qBittorrent's namespace confinement itself still passes; only the tunnel's actual internet path and the stale DNS target are broken, exactly as before this plan started.
- **Why out of scope:** NordVPN/qBittorrent tunnel networking has no relationship to Homebox, Actual, or Donetick's persistence, which is this plan's entire subject. Fixing it would require restoring the NordVPN tunnel and/or correcting `test-forwarding.sh`'s resolver target to a live AdGuard address -- neither touches this plan's file set or objective.
- **Impact on this plan's acceptance criteria:** the plan's literal `make reboot-test-ser8` exits 0" criterion is technically UNMET as a result. Every other acceptance criterion (Homebox/Actual/Donetick pre/post snapshot equality, ownership/mode, and the full household suite passing 8/8 post-reboot) is MET. See `11-06-SUMMARY.md` for the full accounting.
- **Suggested fix (not applied):** restore the NordVPN tunnel (separate operational task, unrelated to this phase) and update `test-forwarding.sh`'s DNS target off the retired pi4 address.
