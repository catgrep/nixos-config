<objective>
Move the flake's nixpkgs input from the EOL `nixos-25.11` channel to `nixos-26.05`, prove both x86 hosts evaluate and remotely dry-activate on it, and make the repository's own gate capable of failing.

Purpose: this is the gate for the entire v1.2 milestone. Nothing else in Phase 9 — the Pi re-platform, the input refresh, the smoketest work, the live activation — is worth starting if ser8 and firebat cannot evaluate on the new channel. It also confirms Success Criterion 3: the 26.05 `services.actual` module exposes real `user`/`group`/`dataDir` options, so Phase 12 will not need an unstable overlay.

Output: a re-locked `flake.nix`/`flake.lock` on `nixos-26.05`, the three 26.05 breaking-change fixes that affect ser8 and firebat, a committed pre-bump evaluation baseline for regression diffing, a reusable array-aware service-diff script, a permanent eval assertion for the Actual module, and a `make check` target whose exit status reflects whether the hosts actually built.
</objective>

- **HIGH — `enabledServices.<host>` is a JSON array, not an object** (`flake.nix:375`, `builtins.filter`). Every assertion in this plan now treats it as an array: capture is `jq -S 'sort'`, the type assertion is `type == "array"`, and set comparison goes through the new `scripts/validation/diff-enabled-services.sh` rather than `jq 'keys'`.
- **MEDIUM — objective claimed dry-activation but only ran `nix build --dry-run`.** Tasks 1 and 2 now run the repository's real remote activation preview (`make dry-activate-ser8`, `make dry-activate-firebat`, `Makefile:242`) in addition to the local dry-run, and the SUMMARY must record both.
- **MEDIUM — baseline capture did not preserve `make check`'s exit status, the command, the timestamp, or tool versions.** Task 1 records the status into a separate `.status` file without aborting the capture, and the remaining provenance into `capture-metadata.json`. Dating the baseline matters because the phase research carries a ~30-day validity window and 26.05 receives continuous backports, so an undated baseline is weak evidence about what the bump changed.
- **LOW — the state-version check only grepped selected paths.** It is now an evaluated assertion across all four hosts.
- **New finding, not in the review — `make check` cannot fail on a host build error.** The recipe's host loop (`Makefile:145-150`) is a single shell command ending in an `echo`, so the recipe's exit status is that echo's. Every plan in this phase gates on `make check` exiting 0; as written that gate is theatre. Task 3 fixes it and proves the fix with a negative test.
