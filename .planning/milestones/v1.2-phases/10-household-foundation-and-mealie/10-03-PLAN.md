<planner_decisions>
**PD-03 — The seeded-data and recipe-persistence assertions are ON by default; the escape hatch is explicit and temporary.** These scripts are written before Mealie is bootstrapped, so on the very first deploy (plan 10-04) there are no Foods, no Units, no recipes, and no images. The tempting design is an assertion that only fires when an environment variable opts *in*, which produces exactly the always-passing check that Phase 9's gap-closure plans had to remove. Instead the assertions are unconditional by default, and `MEALIE_ALLOW_UNSEEDED=1` downgrades them to informational output for the single pre-bootstrap run in plan 10-04. From plan 10-06 onward nothing sets that variable, so `make smoketests-ser8` carries a real check permanently. The script header states this, and states that setting the variable inside `deploy.yaml`, inside `ser8/all.sh`, or inside any committed file defeats the check.

**PD-04 — The Foods and Units table names are treated as unconfirmed.** RESEARCH.md Assumption A3 guesses `ingredient_foods` and `ingredient_units` from the upstream issue tracker, and a `psql` query against a missing table errors rather than failing meaningfully. Write the assertion against those names but resolve each through `to_regclass` first, so a wrong guess produces a named failure instead of a database error. Plan 10-04 confirms the real names against the live schema and corrects this file if the guess was wrong.
</planner_decisions>
