<objective>
Make the engine observable from outside itself, and make the post-deployment checks incapable of
passing when the thing they check is missing.

Purpose: a nightly job that fails loudly is already handled by the mail path. The dangerous case
is the one that stops running and says nothing, and only an external observer sees absence. That
is what the freshness metrics and the alert rules are for — and the reason each rule needs an
explicit absence arm is that a threshold comparison against a series that does not exist
evaluates over an empty vector and never fires, which would make the alerts silently useless in
precisely the situation they were added for. The smoketests are the same principle applied after
deployment: this repository already carries several checks that pass while the thing they test is
dead, and none of the ones added here may join that list.

Output: the exporter pointed at the metrics directory, three absence-safe alert rules in the
existing rule group, and a nine-script fail-closed smoketest suite reached through the host's
existing single entry point.
</objective>

  The governing rule, and the reason this task exists as its own task: this repository already
  has five smoketests that pass while the thing they check is dead — a route check that passes
  with zero routes extracted, a host check that treats a connection failure as no errors, a
  service check that passes while the unit is dead, two host entries that are literally the shell
  builtin that always succeeds, and a subtest group that counts skips as passes. Not one of these
  nine may join that list. Absent artifact, unreachable host, empty command output, or
  unparseable content is a failure with the failed command named in the message.

  The nine:

  1. **snapshot freshness** — the newest automatic daily snapshot of the persisted-state dataset
     exists and its creation time is within 26 hours. No snapshot is a failure, not a skip.
  2. **replica freshness** — the same assertion against the replica dataset on the backup pool.
     Both sides are checked because a source snapshot that is never replicated is a backup that
     dies with the disk it is on.
  3. **dataset properties** — the load-bearing properties on both sides of the replication, in one
     test because they are read the same way and fail for the same kind of reason: someone
     created a dataset by hand without the properties its declaration describes.

     On the replica tree: deduplication off, not automatically mountable, read-only, and no
     dataset anywhere in it with a mountpoint under the live service directory root. The last of
     those is the one that matters most — a replica that inherits a live service's mountpoint will
     shadow that service's data the next time anything mounts everything. Comment that, because
     the assertion looks like paranoia until it is explained.

     On the source children: every child dataset reports access-time updates off *as a local
     property, not an inherited one*, and the database child additionally reports a 16K record
     size, also local. Read these with the source-qualified form so an inherited value cannot
     satisfy the assertion. That distinction is the whole point of the check: inheritance would
     make the values right today and silently wrong the moment a parent property changes, and a
     locally set property is a recorded intent rather than an accident. A child that is missing
     either property was created by hand without them, which is exactly the drift this test
     exists to catch.

     Derive the child list from the configured covered-service set rather than hardcoding it, so
     a service added later is checked without editing this file.
  4. **verification last run** — the verification unit's last invocation succeeded, read from the
     unit's own result state rather than from any file the job wrote, so a job that crashed before
     writing anything still fails this test.
  5. **manifest coverage and hold position** — the newest manifest exists, parses, its header
     status field is the success token, and the set of services it names matches the configured
     covered-service set exactly. This is the inverted assertion in the suite and needs the
     comment discipline the template uses: it deliberately compares against the *declared* set
     rather than against whatever is present, so that a service silently dropped from coverage
     fails rather than quietly narrowing the manifest. Name the condition under which a future
     editor should change it, namely a deliberate coverage change, which should update both
     sides.

     The same test also checks the hold position, because the manifest is where it is recorded
     and splitting the two would mean parsing the same file twice. For every dataset row, the
     sixth field names a snapshot; assert that snapshot still exists on the pool, and that the
     pool actually carries a `last-verified` hold on it. A recorded hold position pointing at a
     snapshot that is gone, or at one nothing is holding, means the last proven-good copy is not
     actually protected — which is the entire guarantee, so it is worth an explicit assertion
     rather than an inference from the manifest alone. An empty hold list for a covered dataset
     is a failure, not a skip.
  6. **dump presence** — the newest snapshot contains a listable custom-format archive for every
     non-template database the host's catalog reports. Derive the expected list from the live
     catalog, not from a constant, so a database added later is checked automatically.
  7. **spot integrity** — pick one database out of the newest snapshot, copy it and its sidecars

     success token. Remove the scratch copy afterwards. This is a spot check that the nightly
     verification's central mechanism still works, run at deployment time rather than at three in
     the morning.
  8. **metrics** — the exporter endpoint on the host serves all six metric names, and the
     snapshot freshness metric's value is within 26 hours. Query the endpoint rather than reading
     the file, because the thing that matters is that the metrics are actually being scraped and
     not merely written.
  9. **no stale persisted directories** — for every service that has a child dataset, the old

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host metrics file → external scraper | The only evidence an outside observer has that the engine ran; its absence is the signal that matters |
| smoketest runner → live host over remote shell | Read-only commands executed against production state, whose output drives a pass or fail verdict |
| alert rule → operator | A rule that cannot fire is worse than no rule, because it is mistaken for coverage |
