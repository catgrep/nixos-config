## Reboot

`NO_CONFIRM=true make reboot-test-ser8` (see Deviations -- the script's
interactive `confirm()` gate needs `NO_CONFIRM=true` for a non-interactive
agent session; this repository's own convention explicitly reserves that
variable for exactly this kind of intentional, plan-authorized operation).

`sudo reboot` was issued and ser8 went down. The wrapper script's own
post-reboot SSH-retry loop (`~1s + 10x5s ~= 51s` budget) is too short for a
real BIOS-to-userspace boot cycle and returned a hard failure
(`Host did not come back online after 10 attempts`) without ever
re-attempting the reboot itself -- no destructive action was retried. Host
reachability was then polled patiently and independently: back online after
~3 SSH attempts at 15s intervals (~30-45s beyond the wrapper's own budget),
confirmed by `uptime` reading `0:00`. `make smoketests-ser8` was then run
directly to complete the verification the wrapper's own target
(`reboot-test-ser8 = reboot-ser8 && smoketests-ser8`) would have run had its
retry budget been long enough.
