<objective>
Restore the frozen media tree into the new mirror via `zfs send/recv` (D-08), start the full application stack in a fixed, documented order (D-16 unmask), and run the doc's Step 5.4 application and storage tests.

Purpose: `zfs send/recv` makes restore integrity intrinsic -- the stream is block-checksummed and verified on receive, bit-identical to the verified staging snapshot by construction, so the doc's original separate full-comparison gate 5.2 disappears (D-08). What remains is confirming the receive succeeded, the mount is correct, every service comes back healthy, and the new pool-health smoketest passes.
Output: `/mnt/media` mounted from `media/data` with the full restored library; all 18 freeze-set services active; test-zfs-media.sh green.

This plan implements Leg 2 of the migration's two-leg data flow (D-06): both staging and the new mirror are ZFS, so `zfs send/recv` replaces a second rsync pass with a block-checksummed stream (D-08).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| zfs send/recv stream -> media/data | The sole data-integrity mechanism for the restore; a corrupted or truncated stream is caught by `zfs recv`'s own checksum validation, not by a separate application-level check |
| Restored mirror -> live application stack | The first real-world exercise of the new mirror under application load since the erase |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-19 | Tampering | zfs recv silently truncates or corrupts the stream without a nonzero exit | high | mitigate | Task 2's action checks `ExecMainStatus` explicitly and scans the journal for stream/pool errors, not just "the unit finished"; the first scrub (Plan 13-07) provides an independent second check |
| T-13-20 | Denial of Service | Samba or an arr service starts before /mnt/media is confirmed mounted, serving a phantom empty directory | medium | mitigate | Task 3's fixed start order gates Samba explicitly on the mount confirmation from Task 2 |
| T-13-21 | Repudiation | Bulk `systemctl start` exit code assumed to mean every listed unit is healthy | medium | mitigate | Task 3's acceptance criteria requires individual `systemctl is-active` confirmation per unit, never a bulk assumption |
</threat_model>
